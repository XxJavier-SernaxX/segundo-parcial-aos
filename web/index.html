Diagrama de Arquitectura Orientada a Servicios

Separación estricta de responsabilidades entre dos APIs independientes en FastAPI y persistencia en Supabase.

Capa de Presentación

Frontend Web (HTML5 + CSS3 + JS)

Consulta mascotas disponibles, registra solicitudes y gestiona resoluciones de adopción.

↓ REST / HTTP (JSON) ↓ REST / HTTP (JSON)
API 1 · Principal (Puerto 8001)

Servicio de Mascotas (FastAPI)

Administra registro, catálogo y disponibilidad de animales.

GET /mascotas • GET /mascotas/{id} • PATCH /mascotas/{id}/estado
REST HTTP Sincrónico ⇄ 1. Valida disponibilidad 2. Notifica estado 'adoptada'
API 2 · Complementaria (Puerto 8002)

Servicio de Adopciones (FastAPI)

Registra solicitantes y gestiona el flujo de aprobación/rechazo.

GET /solicitudes • POST /solicitudes • PATCH /solicitudes/{id}/resolucion
↓ SQL (Esquema mascotas) ↓ SQL (Esquema adopciones)
Persistencia en la Nube

PostgreSQL en Supabase

Esquemas independientes (mascotas y adopciones) sin joins físicos entre sí. Políticas RLS activas.
